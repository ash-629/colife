# CoLife 分步开发计划

版本：v1.0 · 日期：2026-10-08 · 状态：D01–D12 已完成

## 1. 目标与依据

依据 `PRD.md` 和 `PROTOTYPE.md`，将当前浏览器原型逐步建设为具有服务端持久化、真实 Agent 协作和反馈闭环的个人学习与生活管理平台。

当前已具备：七页交互原型、视觉规范、需求与业务规则、原型检查记录。

本轮建设范围：正式应用骨架、服务端业务数据、模型适配、Agent 编排、可靠的提案应用、动态学习与复盘、完整的日程校验。

本计划保留各阶段的工作要求；正式实施结果见 IMPLEMENTATION_LOG.md 和 ACCEPTANCE.md。现有 `prototype/` 保留为设计参照与独立运行入口。

## 3. 分步实施

### D01：明确技术方案与需求契约

**目标**：把产品需求转化为能够直接实施的技术约束。

工作内容：

1. 确定前端框架、服务端技术、数据库、迁移工具、测试与构建方式。
2. 模型供应商确定为 DeepSeek；按照 `MODEL_CONFIGURATION.md` 明确模型接口、超时策略与结构化输出方式，建立统一适配层。配置中的 API Key 初始为空。
3. 确定运行环境、身份与数据隔离方案。首版按个人空间设计；若开放网络访问，身份验证与资源归属检查须纳入基础能力。
4. 编写领域模型、接口契约、错误格式、状态机和需求追踪矩阵。
5. 明确正式日期按用户时区计算，原型固定日期仅用于原型。首版默认时区为 Asia/Shanghai，并预留个人设置。
6. 明确“任务完成”与“目标验收完成”的区别，以及重试、取消、恢复和提案失效规则。

交付物：`docs/ARCHITECTURE.md`、`docs/DATA_MODEL.md`、`docs/API_CONTRACT.md`、`docs/TRACEABILITY.md`。

验收：F01–F07、P01–P07、R01–R09 均有实施位置与验收方式；关键技术决策明确；未确认事项注明影响范围。此步骤不把现有原型的 localStorage 或静态服务器当作正式架构。

### D02：搭建正式工程与基础设施

**目标**：获得能够持续开发和验证的工程基础。

工作内容：

1. 建立正式前端、服务端与共享契约目录；最终目录在 D01 确定。
2. 配置环境变量、开发启动、构建、代码检查、测试与数据库迁移命令。
3. 提供不含密钥的配置示例；真实密钥只由服务端读取。
4. 实现服务健康检查、统一错误处理、请求标识与基础日志。
5. 配置正式页面路由和前后端本地联调。
6. 建立示例数据初始化脚本，区分开发数据与正式数据；重启应用不自动覆盖已有记录。

交付物：可启动的前后端工程、配置示例、开发启动说明、健康检查。

验收：按 README 在干净环境中完成启动；前端可调用健康接口；缺少模型配置时提示清楚，基础业务仍可使用；密钥不进入浏览器资源或版本库。

### D03：建立数据模型与业务服务

**目标**：让业务数据成为所有页面与 Agent 的共同依据。

工作内容：

1. 建立个人空间、目标、里程碑、任务、任务依赖与执行记录。
2. 建立学习路线、阶段、资料条目、笔记、测验、答题记录与薄弱点。
3. 建立习惯、每日打卡、每日精力、可用时间与固定安排。
4. 建立 Agent 配置、运行、运行节点、执行事件、产出、提案与复盘记录。
5. 实现服务端字段校验、状态流转、归属检查、查询与事务边界。
6. 为提案应用、习惯打卡与复习任务生成定义唯一约束和幂等键。
7. 记录创建时间、更新时间、完成时间和数据版本，支持历史查询与过期提案检测。

交付物：数据库迁移、领域服务、业务接口、服务层验证。

验收：记录重启后保留；无效字段或非法状态不能写入；同一习惯同一天无重复记录；跨空间请求不能读取或修改他人记录；多项任务写入可以整体提交或回滚。

### D04：实现页面框架与通用组件

**目标**：将已确认的视觉与交互规则迁移到正式应用。

工作内容：

1. 实现三栏布局、导航、面包屑、七页路由和窄屏协作入口。
2. 抽取目标卡片、任务行、状态标签、进度、Agent 卡片、运行轨迹、图表容器和提案组件。
3. 实现表单、弹窗、详情抽屉、Toast，以及加载、空、失败和禁用状态。
4. 建立请求与页面数据更新机制，修改成功后刷新相关业务查询。
5. 实现键盘焦点、Escape 关闭、未保存提醒与减少动效偏好。
6. 区分本地模拟环境与真实数据环境，正式页面的状态来自服务端。

交付物：应用布局、通用组件、七页框架、请求封装。

验收：七页均可访问；视觉符合原型；窄屏仍能进入协作能力；网络错误有明确反馈；弹窗键盘可操作；空数据可引导用户继续操作。

### D05：实现目标、任务与基础日程

**目标**：先让用户能够独立管理和执行学习生活计划。

工作内容：

1. 实现目标新建、草稿、详情与进度。编辑、归档及目标验收入口按 D01 确定的范围实现。
2. 实现手动任务创建、详情、状态切换、关键词与目标筛选；按已确定范围提供编辑和删除。
3. 实现看板和周日历，使用同一任务数据；支持前后周切换。
4. 实现专注开始、暂停、继续、结束与记录。用开始时间及暂停区间计算时长，界面定时器只负责显示。
5. 实现今日工作台的任务统计、目标进度和专注指标。
6. 提供个人可用时间及固定安排的基础数据入口，为后续日程校验准备条件。

交付物：P01、P02、P04 的手动管理功能，任务与专注服务。

验收：新建目标 → 手动添加任务 → 安排日期 → 执行 → 完成 → 查看进度可完整走通；刷新和重启后数据一致；恢复任务可同步回退进度；已完成任务不会因重新读取而重复累计。

**里程碑 M1**：即使模型服务不可用，用户也能管理目标、任务和日程。

### D06：接入真实模型与 Agent 编排

**目标**：让角色之间通过明确产出进行协作。

工作内容：

1. 建立 DeepSeek 模型适配层，读取服务端配置，统一请求、响应、超时、取消、用量与错误处理；API Key 为空时返回模型未配置状态。
2. 为五个 Agent 定义职责、输入上下文、输出结构和提示词版本。
3. 按目标类型建立执行路径：协调分派 → 学习／生活处理 → 计划整合 → 复盘检查 → 协调汇总。
4. 将角色产出保存为结构化对象，下游读取上游结果；可选角色暂停时跳过，必要角色暂停时阻止发起并说明原因。
5. 对模型结果校验字段、日期、耗时和引用，校验失败不能直接进入业务数据。
6. 保存节点状态和交接摘要；前端通过事件订阅或轮询读取真实进度。
7. 定义有限重试与失败恢复，保留成功节点产出；结果变更时重新执行依赖它的下游节点。
8. 用户取消后中止后续调度；进程中断后将运行恢复为可重试状态，避免永久停留在运行中。

交付物：模型适配、五个角色、运行服务、节点与事件记录、P06 真实执行轨迹。

验收：不同目标获得对应内容；运行进度来自服务端事件；上游结果被下游实际使用；超时、非法输出、暂停角色和取消均有可见结果；运行本身不直接创建已生效任务。

### D07：实现提案确认与完整排期校验

**目标**：把 Agent 产出转换为可审阅、可执行且可恢复的业务操作。

工作内容：

1. 统一新计划、复习、重新排期与复盘建议的提案结构，保存来源运行及关联数据版本。
2. 展示任务、日期、预计耗时、约束、冲突、调整理由及应用前后差异。
3. 用确定性业务规则检查截止日期、每日容量、固定安排和任务依赖；模型负责提出建议，业务服务负责验证。
4. 对不可满足的限制明确说明，并允许用户修改目标条件后重新生成。
5. 实现确认、暂不应用、过期与撤销规则；既有目标取消新提案后保留原有计划。
6. 应用提案时再次校验当前数据，使用事务、唯一约束和幂等键防止重复或部分落地。
7. 重新排期只修改符合条件的未完成任务；保留已完成记录与调整历史。

交付物：提案服务、差异视图、冲突检查、确认与取消接口。

验收：未确认的提案不生成执行任务；并发重复确认只应用一次；失败不留下部分任务；过期提案提示重新生成；超期、容量不足和依赖冲突不能被静默接受；既有目标的重新规划失败不清除原计划。

**里程碑 M2**：创建目标 → 真实协作 → 审阅提案 → 确认任务 → 执行反馈完整可用。

### D08：实现动态学习与知识反馈

**目标**：让学习内容与目标及用户实际掌握情况关联。

工作内容：

1. 从学习 Agent 产出建立学习路线、阶段、里程碑和关联任务，替换固定示例路线。
2. 实现资料条目与笔记管理；用户自行添加资料，Agent 推荐外部链接需标明来源，无法验证的链接不得标为已验证。
3. 根据当前阶段生成测验，保存题目、选项、正确答案、解释与版本。
4. 服务端校验题目完整性，并在提交后统一计分；答题前不向客户端暴露答案字段。
5. 保存答题记录、薄弱点与后续学习建议。
6. 复习建议通过统一提案应用，关联到本次测验，避免重复创建任务。
7. 用户重测产生独立记录，历史反馈可追踪，不直接覆盖过去的学习事实。

交付物：P03 动态学习路线、资料和笔记、测验与反馈服务。

验收：学习路线与所选目标一致；未答完不能提交；重复提交同一次测验不重复记分；薄弱点能够追溯到具体问题；确认复习建议后创建关联任务；笔记刷新后保留。

**里程碑 M3**：学习计划 → 执行 → 测验 → 薄弱点 → 复习任务形成闭环。

### D09：实现习惯与生活上下文

**目标**：让计划能够考虑用户的实际生活节奏。

工作内容：

1. 实现习惯新增、每日打卡与撤销，以及历史记录。
2. 按用户时区计算当日、每周达成率和连续打卡天数。
3. 实现每日精力记录与历史查询，将其与可用时间、固定安排汇总为生活上下文。
4. 生活 Agent 使用这些记录生成负荷建议；数据缺失时说明依据不足。
5. 降低负荷或调整日程的建议进入 D07 提案流程，经确认后应用。

交付物：P05、习惯与精力服务、生活上下文提供器。

验收：同一习惯同一天只能有一个有效打卡；撤销后统计更新；连续天数按真实日期计算；精力更新本身不修改日程；确认调整后才改变任务。

### D10：实现复盘、真实趋势与建议落地

**目标**：使反馈基于真实记录，并能指导下一轮行动。

工作内容：

1. 提供今日和本周查询，统一时区、日期边界和指标定义。
2. 区分计划任务完成率、实际完成任务数、计划耗时、实际专注时长与习惯达成率。
3. 为专注、完成与打卡建立历史聚合查询，替换静态趋势数据。
4. 向复盘 Agent 提供统计事实、执行差异、测验薄弱点和生活状态。
5. 将事实、原因假设、建议分别展示，保存复盘范围、上下文版本和生成时间。
6. 将建议转换为可确认提案；数据不足时提供记录引导，不生成虚构评价。
7. 提供历史复盘查看；同一建议只能应用一次。

交付物：P07、统计服务、复盘服务、历史查询与建议提案。

验收：图表可追溯到业务记录；切换日期范围后所有范围指标一致；新增执行记录会改变对应统计；复盘失败保留已有数据；应用建议后任务真实落地且不重复。

**里程碑 M4**：目标、学习、生活、执行和复盘共享上下文，反馈可进入下一轮计划。

### D11：完善全局集成与可靠性

**目标**：消除模块间割裂与异常情况下的数据不一致。

工作内容：

1. 实现服务端全局搜索，覆盖目标与任务，支持空结果和详情跳转。
2. 接入右侧协作建议与最近活动，使用真实运行和业务事件。
3. 完善 Agent 配置持久化，修改配置影响后续运行，不改变已启动运行的配置快照。
4. 统一加载、空、错误、无权限和提案失效状态；请求失败不误报成功。
5. 处理刷新、重复点击、连接中断、后端重启与模型不可用。
6. 检查各页面日期、数据口径、目标进度和任务状态是否一致。
7. 补齐个人空间数据隔离、敏感配置保护、日志脱敏与备份恢复。

交付物：P01/P06 全局集成、搜索、活动、错误恢复与配置管理。

验收：所有页面使用相同业务事实；修改记录后相关页面及时更新；模型不可用时仍可使用手动管理；用户无法读取其他空间的数据；刷新后不丢失已保存记录，也不会重复应用提案。

### D12：系统验收与发布准备

**目标**：验证产品流程、可靠性和可运行性。

工作内容：

1. 回填需求追踪矩阵，核对 PRD、原型与正式实现。
2. 执行领域规则测试，重点验证状态机、日期容量、依赖、幂等、事务和归属检查。
3. 执行接口测试，验证输入校验、错误码、失败恢复和重复请求。
4. 执行端到端核心场景 S1–S6，包括正常、空数据、失败重试和提案过期分支。
5. 对照原型检查桌面与窄屏布局、表单键盘、弹窗焦点和反馈文案。
6. 执行代码检查、构建与数据库迁移验证；在目标环境执行启动及健康检查。
7. 编写运行、使用、配置、部署、备份与恢复说明，更新实现范围和已知限制。

交付物：`docs/ACCEPTANCE.md`、正式版本检查记录、部署说明、更新后的 README。

验收：核心流程通过；需求矩阵无未说明的遗漏；无阻断问题；部署步骤可复现；真实模型与业务存储工作正常；已知限制可查阅。

**里程碑 M5**：形成具有完整使用说明与验收记录的可发布版本。

## 5. 关键实施规则

1. **业务记录是依据**：目标、任务、日程与复盘采用同一服务端数据源，避免各页面分别维护副本。
2. **提案与执行分开**：Agent 产出建议，用户确认后由业务服务执行。
3. **校验不交给模型决定**：字段、日期容量、依赖、权限与幂等由确定性规则保障。
4. **角色交接可追溯**：保留输入摘要、产出、节点状态与关联运行，不用内部思维链解释产品行为。
5. **迭代不依赖虚构指标**：先使用真实任务、专注、习惯和测验记录，再生成洞察。
6. **上下文按需读取**：每次运行只读取相关目标与记录，不默认把所有个人数据发送给模型。
7. **模拟与真实环境明确区分**：保留独立原型，正式应用运行状态不得以定时动画替代。
