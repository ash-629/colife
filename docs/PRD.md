# 同频 CoLife 产品需求文档

版本：v1.0 · 日期：2026-10-08 · 用途：产品设计、开发实现与功能验收依据

## 1. 需求摘要

CoLife 面向同时管理学习目标与日常生活的个人用户，通过五个职责明确的 Agent，将自然语言目标转换为可执行计划，并依据任务执行、测验和习惯记录持续调整。核心价值是减少反复规划的负担，让学习计划与真实的生活时间保持同频。

本次交付包含 PRD、设计与交互说明、浏览器可交互原型。原型使用模拟 Agent 结果与本地数据，不代表已实现真实模型推理、服务端存储或后台调度。

## 2. 用户与问题

| 用户 | 场景 | 痛点 | 需要的结果 |
| --- | --- | --- | --- |
| 学生与自主学习者 | 两周内学习 React，每晚两小时 | 目标太大、不知道怎么拆解；运动与学习撞期 | 学习路线、每天任务、可验证的里程碑 |
| 工作中的自学者 | 工作之外学习，同时维持运动习惯 | 精力有限、计划经常赶不上变化 | 考虑可用时间和生活约束的安排 |
| 核心用户本人 | 晚间回顾今日执行 | 数据散在多个工具，难以形成反馈 | 汇总执行事实，解释调整原因 |

### 产品原则

1. Agent 有明确输入、产出与交接关系，不能只是五个不同名称的聊天入口。
2. 所有改变日程的建议先展示差异，用户确认后应用。
3. 用可见执行摘要解释协作，不展示或依赖模型内部思维链。
4. 用户可以直接管理任务，Agent 是助手而非操作障碍。
5. 计划、任务、学习记录和复盘共享上下文。

## 3. 用户场景与流程

### S1：创建目标并生成计划

用户在目标页创建“React 学习与项目实践”，填写截止日期、每天可用分钟数、限制与验收标准 → 协调 Agent 建立一次运行 → 学习 Agent 生成路线 → 生活 Agent 汇总限制 → 计划 Agent 安排任务并检测冲突 → 协调 Agent 汇总提案 → 用户预览里程碑、任务与时间安排 → 确认应用 → 目标变为进行中，任务进入工作台与日程。

异常：空标题、过去的截止日期、不可用时间须就地提示；Agent 失败显示出错节点，允许重试；未经确认的提案不能创建执行任务；用户取消可保留目标草稿。

### S2：今日执行

进入工作台 → 查看今天任务与精力状态 → 打开任务详情或专注计时 → 标记完成 → 工作台完成数、看板、目标任务进度同步更新；重复完成不重复计数，允许恢复未完成。

### S3：学习与反馈

进入学习中心 → 查看当前路线与资料 → 记录笔记 → 完成知识测验 → 展示得分与解释 → 学习 Agent 标记薄弱点 → 生成复习建议 → 用户接受后进入任务列表。

### S4：生活约束与重新排期

用户打卡运动、选择今日精力 → 生活 Agent 汇总状态 → 用户发起重新排期 → 展示保留事项与调整项 → 用户确认 → 未完成任务调整日期，已完成任务保留。

### S5：复盘

用户选择今日／本周 → 查看完成率、专注时长、习惯达成、学习薄弱点 → 生成复盘 → 展示事实、建议与调整提案 → 用户确认后将建议落成任务；同一提案只能应用一次。

### S6：管理 Agent

进入协作中心 → 查看角色、启用状态与能力边界 → 配置是否参与协作 → 发起运行 → 查看节点状态、交接摘要与产出 → 遇到失败时重试。生产版需要将用户配置保存到服务端，并在调度中实际使用。

## 5. 功能详细设计

### F01：创建目标

| 输入字段 | 类型 | 必填 | 约束 |
| --- | --- | --- | --- |
| 标题 | 文本 | 是 | 1–60 字，去除首尾空格 |
| 类型 | 枚举 | 是 | 学习／生活 |
| 截止日期 | 日期 | 是 | 不早于当日；原型基准日为 2026-10-08 |
| 每日可用分钟 | 整数 | 是 | 15–480 |
| 验收标准 | 文本 | 否 | 最多 300 字；空时由用户补充或接受提案标准 |
| 时间限制与背景 | 文本 | 否 | 最多 500 字，如周三运动、React 薄弱 |

输出：目标记录、草稿计划、关联运行、里程碑、待确认任务。

状态：草稿 → 规划中 → 待确认 → 进行中 → 已完成；规划失败可以重试，取消提案返回草稿。目标完成在生产版需验收标准确认，不能只凭模型判断。

### F02：Agent 编排与提案

| 角色 | 输入 | 产出 | 边界 |
| --- | --- | --- | --- |
| 协调 Agent | 用户请求、相关目标、个人上下文 | 子任务分派、运行摘要、统一提案 | 不代用户批准计划 |
| 学习 Agent | 目标、学习记录、测验结果 | 路线、测验、薄弱点、复习建议 | 不捏造用户已掌握的能力 |
| 生活 Agent | 可用时间、固定安排、精力、习惯 | 时间与负荷限制 | 不作医疗诊断 |
| 计划 Agent | 学习路线、生活限制、当前任务 | 有日期和耗时的任务、冲突与替代方案 | 不覆盖已完成记录 |
| 复盘 Agent | 计划与实际执行记录 | 事实汇总、原因假设、调整建议 | 区分记录事实与推测 |

每次运行包含唯一运行标识、请求、节点状态、摘要、结果、更新时间。节点状态：等待／运行中／成功／失败／跳过。运行状态：排队／运行中／待确认／已应用／失败／取消。串行依赖满足后才能启动下游；失败保留已完成产出；重试不重复落地任务。禁用必要角色时提示无法生成对应计划。

提案必须显示：目标、拆解后的任务、预计耗时、日期、约束、调整理由、确认按钮。原型采用固定模板并用用户标题和可用时间填充，逐步动画只模拟执行进度。

### F03：任务与日程

字段：任务标题、目标关联、状态、优先级、日期、预计分钟、实际分钟、来源、备注。状态：待办 → 进行中 → 已完成；可恢复为待办。优先级：高／中／低。手动任务和 Agent 任务使用同一列表。

操作：按关键词与状态筛选；切换看板与周日历；查看详情；标记完成／恢复；专注计时；查看下一周／上一周；重新排期并预览。周日历显示具体日期，任务过期不自动算完成。生产版依赖任务尚未完成时需提示，原型仅展示顺序路线，不实现复杂依赖图。

进度：完成任务数 ÷ 关联任务总数；无任务为 0%。完成率与时间使用记录事实计算。原型专注计时完成后累计真实经过秒数，不把页面退出时间自动算作专注。

### F04：学习中心

包含当前学习路线、阶段主题、关联任务、资料卡片、笔记与测验。笔记字段：标题 1–60 字，正文 1–2000 字；保存后可以重新编辑。示例测验 3 道单选题，每题 1 分；提交前必须答完；提交后展示解释，重新测验清除上次选择。

测验低于 100% 展示复习建议；确认后创建一条关联学习目标的复习任务，重复点击不得重复创建。原型资料为产品内的示例学习内容，无外部真实性承诺。

### F05：习惯与精力

默认习惯：阅读、运动、早睡。按日期记录，每项每天一次；再次点击撤销当天记录。新增习惯名称 1–30 字，目标描述 1–60 字。精力：充沛／一般／疲惫，每日一个状态。连续天数以真实连续日期记录计算，原型不把历史静态示例计为用户打卡。

重新排期使用当日精力与可用时间生成差异；不能悄悄修改日程。原型疲惫状态将一个当日未完成任务移至次日，用于验证确认流程。

### F06：复盘与洞察

输入：日期范围、范围内任务与完成记录、专注时长、习惯记录、测验。输出：事实指标、计划偏差、薄弱点、建议与可应用调整。图表历史示例需标“示例趋势”，不能当作用户数据。

空记录时引导完成任务和打卡，不生成虚构评价；生产版复盘失败保留原有记录。原型提供基于本地状态的模板复盘，并可创建一条“复习与次日规划”任务。

### F07：全局交互

搜索覆盖任务与目标，选择结果进入目标页或任务详情。弹窗支持 Escape 关闭、焦点管理；有未保存表单时关闭提示。操作反馈有成功提示、字段错误和运行错误三种。重置原型数据需要二次确认；浏览器存储不可用时提示只能保存到本次会话。

## 6. 业务规则

| 编号 | 规则 | 优先级 |
| --- | --- | --- |
| R01 | 未确认提案不进入任务列表 | P0 |
| R02 | 同一提案仅能应用一次 | P0 |
| R03 | 已完成任务不能被自动重新排期 | P0 |
| R04 | 每项习惯每天只能打卡一次，可撤销 | P1 |
| R05 | 同一测验反馈的复习建议仅生成一条任务 | P0 |
| R06 | 任务、目标、工作台与复盘采用相同数据源 | P0 |
| R07 | 运行失败可见，允许重试，不重复副作用 | P0 |
| R08 | 原型基准日期固定为 2026-10-08，所有页面一致 | P0 |
| R09 | 模拟执行与示例趋势必须显式标记 | P0 |

## 7. 版本规划与非目标

| 阶段 | 工作内容 | 完成标准 |
| --- | --- | --- |
| 产品设计 | PRD、视觉规范、可交互原型 | 核心页面、用户流程与业务规则完整且一致 |
| 基础版本 | 目标与任务管理、数据持久化、统一上下文 | 目标创建、任务管理、日程与状态同步可用 |
| 协作能力 | 真实模型、Agent 编排、结构化结果、失败重试 | 计划提案可审阅、可确认、失败可恢复 |
| 反馈闭环 | 测验、习惯、复盘与提案应用 | 学习与执行反馈能形成可应用的调整建议 |
| 发布验收 | 功能验收、缺陷修复、运行与使用文档 | 关键验收项通过，运行与使用说明齐备 |

版本迭代优先贯通 S1、S2、S3、S5 的完整业务流程，再完善生活管理与 Agent 配置。各阶段以完成标准和验收结果作为进入下一阶段的依据。

当前原型非目标：真实模型 API、用户鉴权、服务端数据库、通知推送、跨设备同步、第三方日历、抓取外部知识库、复杂 RAG、团队协作、多租户、医疗建议。基础版本优先实现服务端持久化与必要的身份验证，协作能力阶段接入真实模型，其余能力作为后续扩展。

## 8. 验收标准与指标

| 编号 | 验收动作 | 预期 |
| --- | --- | --- |
| A01 | 创建有效目标 → 模拟协作 → 确认提案 | 目标出现、3 条关联任务落地、再次确认不重复 |
| A02 | 空标题或日期早于原型基准日 | 表单阻止提交并显示原因 |
| A03 | 完成一条任务 → 返回工作台与目标 | 完成数、看板、目标进度一致；恢复后同步回退 |
| A04 | 协作失败 → 重试 | 显示失败节点；重试后产出提案 |
| A05 | 打卡 → 刷新 → 撤销 | 状态保留；撤销后达成数减少 |
| A06 | 完成测验 → 接受复习建议 | 正确计分、解释可见、只创建一条复习任务 |
| A07 | 疲惫 → 重新排期 → 确认 | 差异可见；只改变未完成任务 |
| A08 | 生成复盘 → 应用建议 | 使用本地执行数据、任务真实进入列表 |
| A09 | 搜索与七页导航 | 所有入口可达，空结果有提示 |
| A10 | 刷新原型 | 目标、任务、笔记、习惯、Agent 配置保留 |

验收目标：七页可达率 100%；上述主流程全部通过；核心阻断缺陷 0；表单和弹窗键盘可达。上线后的学习完成率、计划采纳率与留存率需真实用户数据验证，本次不编造业务 KPI。

## 9. 非功能需求

| 维度 | 要求 |
| --- | --- |
| 体验 | 桌面优先，1440px 三栏；窄屏收起右侧面板，导航仍可达 |
| 反馈 | 普通操作即时反馈；运行显示阶段；禁止无反馈长等待 |
| 无障碍 | 语义按钮、表单 label、可见焦点、弹窗焦点管理、减少动态效果偏好 |
| 数据可靠性 | 写入失败提示，损坏的本地数据回退初始数据，重置前确认 |
| 安全 | 原型不存 API 密钥；用户文字按纯文本处理；生产版密钥置于服务端 |
| 性能 | 原型普通交互目标 200ms 内反馈；无需请求远程字体／图片 |
| 兼容 | 验收桌面 Chromium；其他浏览器待正式开发验证 |
| 国际化 | 本次中文 UI，英文仅品牌和角色辅助标签 |

## 11. 一致性自检

- 七个页面均可追溯 S1–S6，主流程均有对应功能和验收项。
- 目标与任务共享关联关系；复盘基于执行记录；提案有确认与幂等规则。
- 模型接入为后续正式开发范围，与当前模拟原型边界一致。
- 未锁定正式技术方案，未知事项集中记录，无空白占位字段。

使用步骤与原型覆盖矩阵见 `PROTOTYPE.md`；运行方法见工程根目录 `README.md`。

## 12. 正式版本实施对照（2026-10-08）

正式版采用 React / TypeScript / Fastify / SQLite，真实接入 DeepSeek，七页与学习生活闭环已实现。前文涉及固定日期、3条任务、示例测验和模拟执行的描述仅针对独立 prototype；正式版按当前用户时区、模型结构化产出和服务端真实记录执行。正式任务数量和测验题数可变，不固定为原型示例数量。首版采用本机个人空间，所有业务请求固定归属个人工作区；不提供公网多用户登录。

最终架构、字段、接口、分步实施、需求追踪与验收分别见 ARCHITECTURE.md、DATA_MODEL.md、API_CONTRACT.md、IMPLEMENTATION_LOG.md、TRACEABILITY.md、ACCEPTANCE.md。
